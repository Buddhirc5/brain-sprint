# Ant Arena — Supabase backend

Production backend for the white-label, multi-tenant quiz app: Postgres with Row Level Security,
SECURITY DEFINER functions for every write, Supabase Auth (password, magic link, 6-digit email code,
Microsoft, anonymous guests, TOTP MFA) and Realtime. The client is `src/api/supabase/` and implements
the same `Api` contract as the in-browser demo (`src/api/demo/`), with the same rules.

## 1. Create the database

**Option A: dashboard (no tools).** Open your project → **SQL Editor** → paste and run, in order:
`migrations/0001_schema.sql` → `0002_security.sql` → `0003_functions.sql` → `0004_question_images.sql` → `0005_live_player_count.sql` → `0006_super_self_approve.sql` → `0007_rename_ant_arena.sql` → `0008_special_characters.sql` → `0009_super_requires_authenticator.sql` → `0010_mfa_reset_by_email.sql` → `0011_private_invite_links.sql` → `0012_certificate_signature.sql` → `0013_poll_slide_types.sql` → `0014_super_admin_authenticator_only.sql` → `0015_passwords.sql` → `0016_units_and_live_join.sql` → `0017_new_types_second_chance.sql` → `0018_story_mode.sql` → `0019_store_pets_rides.sql` → `seed.sql`.

**Updating an existing project:** run only the new migrations, in number order. Every migration from 0016 on is safe to run more than once.

**Option B: CLI.**
```bash
supabase link --project-ref <your-project-ref>
supabase db push --include-seed        # older CLIs: db push, then run seed.sql in the SQL editor
```

Re-running `seed.sql` is safe. After changing `src/data/library.json`, run `node scripts/sb_gen_seed.mjs`
and run `seed.sql` again (or edit the library from the super admin console).

## 2. Make yourself super admin

In the **SQL Editor** (this function can't be called from the app):
```sql
select public.bootstrap_super_admin('you@yourcompany.com');
```
Sign in to the app with that email (it must be confirmed) and password at `#/super`, then set up
an authenticator app (scan the QR code, enter the 6-digit code). The database only treats you as a
super admin in a session verified with the authenticator (`aal2`). The console signs out after 15
minutes idle. Every super admin action is audited.

**Microsoft sign-in (optional).** In Entra ID, register an app (single tenant is recommended for one
company). Set the redirect URI `https://<project-ref>.supabase.co/auth/v1/callback` and create a
client secret. In Supabase → Providers → **Azure**, enable it and enter the client ID, the secret and
the URL `https://login.microsoftonline.com/<tenant-id>/v2.0`. Then turn on `signIn.sso` in the
tenant's settings. The client asks for the `email` scope.

## 4. Front-end environment (Vercel → Project → Settings → Environment Variables)

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon / publishable key>
```
Never put the service-role key in the front end. The client uses the PKCE auth flow: sign-in
redirects come back as `?code=…` and leave the `#/route` alone. They must open in the same browser
that asked for them, which is normal for magic links.

## 5. Per-tenant time zone

"Today" (quiz `date`/`until`) and streak days use `tenants.tz` (IANA name, default `UTC`).
It isn't part of the TypeScript `Tenant` type yet, so set it in SQL:
```sql
update public.tenants set tz = 'Asia/Colombo' where slug = 'acme';
```

## Security model

- **All writes go through functions.** `anon` and `authenticated` have **no** INSERT/UPDATE/DELETE on
  any table. Every RPC is `SECURITY DEFINER` with `search_path = ''`. Each one checks the caller's role
  (viewer < host < editor < admin < owner; super admin = owner everywhere) and writes an audit row
  like the demo does.
- **RLS on every table.** SELECT is granted only where Realtime or the app needs it, and filtered by
  policy. Admins (any role, aal2 when the tenant requires MFA) read their tenant. Players read released
  quizzes, gifts and disqualifications of their own tenant. Live participants read their session row
  and their own live-player row. Poll audiences read the poll row and a "pulse" counter only.
- **Answer keys never reach players.** `quizzes.questions` has no answers **and no explanations**
  (explanations often give the answer away). Both live in `quiz_keys`, which only admin roles can
  read. Live-game answers are copied into `live_keys`, which nobody can read. Players get quiz and
  leaderboard data through `tenant_snapshot()`, which masks it: other players' Employee IDs are masked
  (`••42`), emails and sign-in history are removed, **other players' chosen answers are removed**, and
  a certification attempt that can still be retaken hides right/wrong.
- **Server-side timing.** `show_question` stamps `q_at`. `answer` measures from it, or from the
  previous answer if the client skipped it. The whole-quiz clock (`limitMs`) and `GRACE_MS` (1.5 s)
  are enforced. Live answers are timed from `q_started_at`.
- **Identity.** Admin membership and email linking use the email in `auth.users` only when it is
  confirmed. Anonymous users can never hold an admin role. Tenant `adminMfa` means roles count only in
  an `aal2` session.
- **Rate limits.** Employee-ID lookup and claim: 5 misses, then a lock of 1 min doubling to 10 min per
  user, plus 100 misses per IP. PIN and poll-code guesses: 10 per user, plus 200 per IP. Q&A: 5
  questions per person. Failures are recorded even though the
  call reports an error: those functions return `{error:{…}}` so the counter isn't rolled back.
- **Errors** are `'<code>: message'` or `'rate_limited:<waitMs>: message'`, and `errors.ts` maps them
  to `ApiError`.

## Realtime & free-tier notes

- Published tables: `tenants, tenant_members, quizzes, quiz_keys, players, runs, gifts, disqualified,
  rosters, audit_log, live_sessions, live_players, live_answers, polls, poll_pulse, poll_responses`.
  `postgres_changes` applies the same RLS, so hidden columns stay hidden: they live in tables the
  subscriber can't read.
- Admin dashboards stream changes (filtered by `tenant_id`) and re-fetch the snapshot at most once
  every 1.5 s. **Players poll every 60 s** (plus `refresh()`), so they don't use Realtime connections.
- Live games and polls subscribe to the specific session or poll rows, re-fetch the view (~250 ms
  debounce) and also poll every 5 s. If the socket isn't connected (for example the limit is reached),
  they poll every 2–3 s instead, so they keep working without Realtime.
- **Free tier:** 200 concurrent Realtime connections, 500 MB database, 5 GB egress. **Projects pause
  after 7 days without activity.** Upgrade to Pro, or keep the project busy, for anything used weekly.
  For live games with more than ~150 people on the free tier, expect some players to fall back to
  polling. That's fine, just a little less instant.
- The tenant snapshot returns every player's plays, as the `TenantData` contract requires. Use
  **Security → purge old plays** (retention) to keep it small for big tenants.

## RPC reference

All take named `p_…` parameters and are called by `src/api/supabase/index.ts`.
Only `tenant_public` works without signing in. Everything else needs a session, which can be anonymous.

| Area | Function | Min. role | Notes |
|---|---|---|---|
| Tenants | `tenant_public(p_slug)` | anyone | `TenantPublic` |
| | `my_access(p_tid)` | signed in | `{role, isSuper}` |
| | `accept_invites()`, `my_tenants()` | signed in, confirmed email | |
| | `tenant_snapshot(p_tid)` | admin → full; player → masked; others → settings only | `TenantData` |
| Players | `my_player`, `player_lookup` (rate limited), `player_claim` (rate limited), `player_register` (allowlist), `player_link_email`, `update_my_card`, `buy_item` | player | coins/levels/streaks computed in `private.player_stats` = `statsOf` |
| Plays | `start_run`, `show_question`, `answer`, `finish_run` | player | server clock (`limitMs`: sprint clamp(min‖2, 0.5, 10), cert clamp(min‖10, 1, 180), story 60 minutes), `runPoints`, cert pass/attempts. Swipe / bucket / story answers score a share (`f`, 100 × f, no speed bonus unless fully right); Story Mode answers never get a speed bonus. Runs store the quiz `kind`; **cert runs never count** toward points, coins, levels or streaks |
| | `retry_answer(p_tid, p_gid, p_index, p_choice)` | player | Second chance: once per missed question of a finished non-cert play, untimed; `rp` capped so the answer stays below a first-try right one (`private.retry_pts`) |
| Quizzes | `save_quiz`, `set_quiz_status`, `delete_quiz`, `import_library` | editor | maker-checker |
| Admin | `save_config`, `save_brand`, `admin_patch_player`, `admin_sign_out_player`, `admin_delete_player`, `admin_reset_run`, `admin_import_players`, `save_dq`, `save_roster`, `save_gift`, `delete_gift`, `purge_runs` | admin | audited |
| | `invite_admin`, `set_admin_role`, `remove_admin` | admin (owners by owner) | keeps ≥ 1 owner |
| | `audit_add(p_tid, p_entry)` | viewer | UI events (exports…) |
| | `library_list()` | any tenant admin / super | contains answers |
| Live | `live_create` | host | 6-digit PIN, keys copied to `live_keys` |
| | `live_control(p_sid, p_action, p_arg)` | host | start / reveal / board / next / end / kick |
| | `live_host_view(p_sid)` | host | `LiveHostView` + `serverNow` |
| | `live_find(p_pin)` (rate limited), `live_join`, `live_player_view`, `live_answer` | signed in | game-show points, streaks; results and `ahead` (player directly above) hidden until reveal |
| Polls | `save_poll`, `delete_poll` | editor | unique 6-digit code |
| | `poll_control`, `qa_moderate` | host | |
| | `poll_find` (rate limited; returns `{pollId, title, slug}`), `poll_public`, `poll_results`, `poll_respond`, `poll_my_responses`, `qa_vote` | signed in | results: raw rows (pseudonymous `who`), aggregated in the client with `engine.aggregate` |
| Super | `super_status`, `super_unlock`, `super_lock`, `super_change_code` | super-admin email | bcrypt code |
| | `super_tenants`, `super_create_tenant`, `super_update_tenant`, `super_delete_tenant`, `super_admins_list`, `super_invite`, `super_audit_list`, `super_save_library` | unlocked super | |
| Setup | `bootstrap_super_admin(email)` | SQL editor / service role only | |

## Testing

```bash
supabase start                        # local stack (needs Docker)
supabase db reset                     # applies migrations + seed.sql
node scripts/sb_test.mjs              # uses the CLI's default local URL/keys
# optional SQL-vs-TypeScript coin/streak parity check:
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:54322/postgres node scripts/sb_test.mjs
```
The test signs up admins with a password (so local email confirmations must be off, as in
`config.toml`), passes MFA with real TOTP codes and uses anonymous players. It exercises every flow
and tries to break the rules with raw table access. It creates fresh tenants each run.
